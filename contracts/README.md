# Обмен данными с системой клиники — ЧЕРНОВИК

Статус: **черновик для обсуждения с командой.** Поля и адреса уточняем вместе до начала работы над
каждой частью. Пункты «Открыто» — решения клиники, которых ещё нет: не достраивайте их сами, спросите.

## Как устроено

- Главная система расписания и карточек пациентов у клиники сейчас — МИС **SQNS**. С SQNS разговаривает
  только наша система; модули команды разговаривают с **нашей системой** по адресам ниже.
- Модули команды работают на заглушке (`web/mock/`). Подключение настоящих данных делаем мы.
- Время — ISO 8601 с зоной Москвы (`2026-12-01T10:00:00+03:00`). Деньги — строкой с копейками (`"3500.00"`).
- Нет данных — `null`, не `0` и не пустая строка. «Нет данных» и «ноль» на экране — разные вещи.
- Ошибка — HTTP-код и `{"detail": "текст по-русски для сотрудника"}`. МИС не ответила — `503` с понятным
  текстом; экран показывает его и кнопку «Повторить», а не пустой день.
- Формат приёма — `format: "clinic" | "online"`. Старые адреса окна врача отдают его как `online: true/false`.

### Номера

- `doctor_id` — **номер врача в нашей системе.** У одного врача в МИС может быть несколько карточек
  (например, отдельная «онлайн»); номер врача у нас один. Номера карточек МИС модули не используют.
- `patient_id` — **номер пациента в нашей системе**, не номер карты МИС.

### Вход

- Адреса `/api/...` — для сотрудников клиники, вход общий (кука). В заглушке входа нет.
- Адреса `/api/public/...` — для сайта, без входа (самозапись пациентов). Защиту от спама и лишних
  запросов делаем мы.

## Роли

У сотрудника может быть несколько ролей (например, на время замены). `GET /api/me` отдаёт список.

| Роль | Что в расписании и документах |
|---|---|
| Администратор | запись, перенос, отмена, «не пришёл», подтверждение; оформление пациента; печать документов |
| Управляющая | графики врачей; свободные окна; где всё занято; раскладка врачей по кабинетам; отметка «принимает детей»; журнал отказов; правка шаблонов и пакетов |
| Главный врач | смотрит расписание; шаблоны не правит |
| Владелец | загрузка врачей и кабинетов; правка шаблонов и пакетов |
| Врач | своё расписание — в окне врача (уже есть, `web/src/doctor`) |
| Пациент (сайт) | самозапись: свободные окна по врачу или специальности |

## Уже есть: окно врача

| Адрес | Ответ |
|---|---|
| `GET /api/doctor/schedule?date_from&date_to` | `{linked, rows: [{visit_id, starts_at, ends_at, patient_name, services[], online, status, unpaid}]}` |
| `GET /api/doctor/earnings` | заработок врача за месяц |
| `GET /api/doctor/changes` | `{changed_at}` — когда менялась запись врача; окно перечитывает расписание |

ИИ-агент встраивается в окно врача. Результат агента — текст черновика медкарты для копирования в МИС
(API для медкарт у SQNS нет).

## Расписание

| Адрес | Что |
|---|---|
| `GET /api/visits?date_from&date_to&doctor_id&room_id` | записи: `[{id, patient_id, patient_name, doctor_id, service_ids[], starts_at, ends_at, room_id, format, status, confirmed, unpaid}]` |
| `GET /api/slots?date_from&date_to&doctor_id&specialty&service_id&format&child&part_of_day` | свободные окна: `[{doctor_id, starts_at, ends_at, format, room_id, price}]`; цена — на дату приёма; `child=true` — только врачи с отметкой «принимает детей» |
| `POST /api/visits` | новая запись `{patient_id, doctor_id, service_ids[], starts_at}` → `{id, confirmed: false}` |
| `POST /api/visits/{id}/confirm` | запись подтверждена (администратор дозвонился) |
| `POST /api/visits/{id}/cancel` | отмена |
| `POST /api/visits/{id}/no-show` | отметка «не пришёл» |
| `GET /api/room-plan?date` | раскладка: `[{doctor_id, room_id, from, to, outside_clinic}]`; `outside_clinic: true` — врач вне клиники, принимает онлайн, кабинет не занят |
| `PUT /api/room-plan?date` | сохранить раскладку дня (Управляющая) |

Правила:

- **Перенос** = новая запись + отмена старой. Отдельного «перенести» нет — так наш расчёт его узнаёт.
- Вид отмены (перенос, заранее, поздняя, неявка) считает наша система по времени записи и отмены.
  Кнопки «Отменить» и «Не пришёл» — это отметки администратора, из них расчёт и исходит; модуль вид
  отмены сам не вычисляет.
- Онлайн-приём врача, который в этот день в клинике, занимает его кабинет. Врач «вне клиники» —
  его приёмы в колонке «Онлайн».
- Новая запись — неподтверждённая (`confirmed: false`); неподтверждённые на сегодня и завтра
  подсвечены и собраны в список «обзвонить».

### Подсказки в записи

Считает наша система, модуль только показывает:

| Адрес | Ответ |
|---|---|
| `GET /api/patients/{id}/summary` | `{first_visit, no_shows, late_cancels, unpaid_visits}` |
| `GET /api/waitlist/count?doctor_id&specialty&date` | `{waiting}` — сколько ждут окно; клик открывает наш лист ожидания |

Считает модуль сам, по записям и раскладке:

- **Накладки:** пересечение записей одного пациента; приём без раскладки по кабинету; два врача в одном
  кабинете в одно время.
- **Следующий визит:** в конце приёма — «через N недель» и сразу запись; список «Пора на повторный».

## Пациенты

| Адрес | Что |
|---|---|
| `GET /api/patients?query` | поиск по ФИО, телефону, номеру карты |
| `GET /api/patients/{id}` | карточка — поля как в `templates/README.md` (`patient.*`) |
| `POST /api/patients`, `PATCH /api/patients/{id}` | создать, поправить |
| `PUT /api/patients/{id}/representative` | Заказчик (представитель) и документ о полномочиях |

Паспорт и адрес пациента клиника начнёт хранить у себя после оформления документов по персональным
данным. До этого модуль работает только на заглушке.

## Решено

- **Экран раскладки «врач — кабинет — часы» делает команда.** Ведёт раскладку Управляющая.
- **Отметку «принимает детей» у врача и фильтр «взрослый/ребёнок» делает команда.** Ведёт Управляющая.
- **Шаблоны документов, их версии и журнал правок хранит модуль команды.** Модуль будет работать на
  сервере клиники, поэтому напечатанные документы с данными пациентов остаются у клиники.
- Передача записей и кабинета в SQNS — наша часть. Модуль только вызывает адреса выше.
- Подтверждение записи сообщением пациенту и кнопка «Написать» — позже, нашими силами. В модуле
  нужно только место под кнопку.
